# CPS Problem Solver — Context, Problem, Solution

CPS는 중단된 작업을 다른 세션에서도 같은 기준으로 이어가기 위한 작업 기억이다. 사용자 의도와 제약, 방향성, 설계 기준을 우선 보존하고, 문제와 해결책을 선택한 이유를 연결한다. 마지막 상태만 남기는 진행표나 대화 전체를 복사하는 로그로 사용하지 않는다.

기존 결과물이 없어도 비슷한 수준으로 재구성할 수 있도록 핵심 구조·명세·품질 기준을 남긴다. 기록에 없는 세부 내용까지 원본과 동일하게 복원한다고 보장하지 않는다.

## 적용 범위와 파일 하나 원칙

- 사용자가 CPS 사용을 요청했거나 동의한 작업에 적용한다. 스킬 자체의 검토·편집 요청을 해당 작업에 CPS를 사용하라는 승인으로 해석하지 않는다.
- 사용자가 지정한 작업 폴더의 `CPS_STATE.md` 하나를 생성하고 갱신한다. 이미 지정된 상태 파일이 있으면 이름을 바꾸거나 새 파일을 만들지 않고 그 파일을 사용한다. 폴더가 불명확하면 먼저 확인한다.
- 실제 결과물은 작업에 필요한 형식으로 만든다. CPS 때문에 별도 매니페스트, 인덱스, 로그, 섹션 파일, 아카이브, 백업 문서를 추가하지 않는다.
- 기존 파일이나 과거 작업은 사용자가 현재 작업에 포함한 범위에서만 읽는다. 같은 폴더에 있다는 이유로 다른 작업의 기록을 읽거나 덮어쓰지 않는다.
- 구형 `DYNAMIC_MANIFEST.md`, `Master_Index.md`, `Analysis_Log.md`는 사용자가 재개 입력으로 지정했을 때만 읽고 하나의 상태 파일로 통합한다. 원본 삭제는 별도 승인을 받는다.

## 무엇을 기록하는가

처음부터 필요한 사실을 기록한다. 매 대화나 도구 출력을 복사하지 않는다. 다음 틀을 상태 파일 안에서 사용하고, 내용이 없는 항목은 억지로 채우지 않는다.

```markdown
# CPS — 작업 이름

## Context
- 목적과 사용자 의도:
- 범위·제약·금지 사항:
- 방향성과 설계 기준:
- 결과물의 핵심 구조·필수 내용·품질 기준:

## Problem
- 해결해야 할 문제와 영향:
- 시도했으나 실패하거나 기각한 접근 → 이유:
- 아직 확인하지 못한 사실:

## Solution
- 채택한 해결책과 현재 명세:
- 중요한 결정: 문제/변경 계기 → 선택 → 이유 → 현재 작업에 미친 영향
- 사용자 승인 범위와 아직 제안인 내용:

## 재개 지점
- 마지막 갱신:
- 현재 목표와 마지막으로 확인한 작업:
- 검증한 결과와 미검증 사항:
- 관련 파일 경로·역할·존재 여부:
- 다음 행동과 그 이유:
- 열린 이슈·승인 대기 사항:
```

파일 경로만 남기지 않는다. 결과물의 필수 구성, 중요한 수치·인터페이스·표현 기준 등 재구성에 필요한 정보를 함께 남긴다. 외부 원본이 없으면 복원할 수 없는 데이터나 자산은 그 한계를 명시한다.

## 언제 어떻게 갱신하는가

다음 시점에 같은 파일의 해당 항목을 갱신한다. 세션 종료까지 미루지 않는다.

1. 사용자 의도·제약·방향성·설계 기준이 바뀌었을 때.
2. 중요한 문제, 해결책, 실패 원인 또는 설계 결정이 확정됐을 때.
3. 의미 있는 작업 단계를 완료했을 때, 중단하거나 인계하기 직전.

단순 조회나 사소한 수정마다 기록을 추가하지 않는다. 현재 상태·다음 행동·검증 결과는 최신 사실로 수정하되, 앞선 의도와 결정 이유까지 최신 상태로 덮어쓰지 않는다. 설계 기준이 바뀌면 이전 기준, 변경 계기, 새 기준의 관계를 남긴다.

예: “표 작성 완료”만 기록하면 다음 세션은 표를 선택한 이유를 모른다. “서술형 초안에서는 조건 비교가 어려웠다 → 사용자가 비교표를 선택했다 → 각 행에 조건·동작·예외를 함께 둔다 → 다음 작업은 예외 누락 확인”처럼 문제와 현재 작업을 연결한다.

일상적인 상태 필드 갱신과 과거 기록 삭제를 구분한다. 완료 내역·실패 이력·결정 근거를 없애는 변경은 아래 정리 절차를 따른다. 기록 수정은 부분 갱신을 우선하고, 저장 후 한글과 변경 내용이 온전한지 확인한다.

## 분량: 평소 약 2,000토큰, 최대 기준 3,000토큰

- 기준은 상태 파일 전체다. 평균적인 관리 목표를 약 2,000토큰으로 두되, 짧은 기록을 채우거나 긴 기록을 자동으로 줄이지 않는다.
- 중요한 갱신 시 이용 가능한 토크나이저로 크기를 확인한다. 정확히 셀 수 없으면 추정치임을 밝힌다. 글자 수를 정확한 토큰 수처럼 보고하지 않는다.
- 3,000토큰에 도달했거나 다음 갱신으로 초과할 것으로 보이면 사용자에게 현재 분량과 추가할 내용을 알리고 처리 방법을 묻는다. 이미 초과한 기록을 발견했어도 임의로 잘라내지 않는다.
- 선택지는 완료 기록 중 승인된 항목 정리 또는 사용자 허용에 따른 한도 조정이다. 응답 전에는 초과를 유발하는 후속 작업을 진행하지 않는다. 새로 확정한 내용을 조용히 누락하지 말고 반영 대기 내용과 이유를 사용자에게 보여준다.
- 자동 압축·요약 재작성·오래된 순서의 삭제·별도 파일로 분할하여 한도를 우회하는 행동을 금지한다. 별도 보관이나 파일 분리는 사용자가 기존 한 파일 원칙을 명시적으로 바꿀 때만 한다.
- 사용자가 선택한 처리 방법과 변경된 한도는 같은 파일에 기록한다. 2,000토큰은 강제 상한이 아니며, 토큰 수는 구독 사용 한도의 비율을 뜻하지 않는다.

## 완료 기록과 중간 산출물 정리

완료 여부만으로 삭제하지 않는다. 앞으로의 재개·재구성·검증에 필요한지를 판단한다.

| 보존할 정보 | 정리 후보가 될 수 있는 정보 |
|---|---|
| 사용자 의도·제약·설계 기준 | 완료한 세부 체크리스트와 중복 상태 보고 |
| 채택한 해결책과 선택 이유 | 해결 후 더는 근거로 쓰이지 않는 임시 조사 메모 |
| 반복 실패를 막는 시도·기각 이유 | 최종본에 반영됐고 재현·검증에도 필요 없는 중간 산출물 |
| 현재 작업에 영향을 준 변경 흐름 | 대체 자료가 확인된 임시 파일 |

삭제 전에 후보 기록 또는 파일 경로, 삭제 이유, 남는 근거와 영향을 보여주고 **사용자가 승인한 항목만** 삭제한다. 포괄적인 작업 진행 승인이나 CPS 사용 동의를 삭제 승인으로 간주하지 않는다.

중간 파일은 최종본 반영 여부, 다른 파일의 참조, 재현·검증 필요성을 확인한다. 유일한 원본·증거·검증 자료나 남은 작업의 의존 파일은 보존한다. 내용이 바뀐 후보나 추가 후보에 이전 승인을 확대 적용하지 않는다. 삭제 후 필요한 근거가 남아 있는지, 상태 파일이 삭제한 파일을 필수 입력으로 가리키지 않는지 확인한다. 정리 결과는 같은 파일의 현재 상태에 반영하고 별도 정리 로그를 만들지 않는다.

## 새 세션에서 재개

1. 사용자가 지정한 작업의 상태 파일을 읽고 의도·제약·설계 기준 → 문제와 결정 이유 → 마지막 작업 순서로 복원한다. 관련 결과물은 필요한 부분만 확인한다.
2. 현재 지시와 기록이 다르면 현재 사용자의 명시적 지시를 우선하고 변경 이유를 기록한다. 출처가 불명확하거나 제안만 된 내용을 승인된 결정으로 승격하지 않는다.
3. 확인된 승인 범위는 유지하고 같은 승인을 반복해서 묻지 않는다. 승인이 필요한 행동인데 근거가 없거나 모호할 때만 해당 부분을 확인한다.
4. 결과물이 없으면 즉시 처음부터 재작업했다고 간주하지 않는다. 기록된 구조·명세·품질 기준으로 복원할 수 있는 부분과 빠진 정보를 구분하고, 재개에 필요한 누락만 확인한다.
5. 사용자에게 복원한 목적·핵심 결정 이유·마지막 상태·바로 이어갈 행동을 짧게 알린 뒤 승인 범위 안에서 계속한다. 다음 행동이 비어 있다는 이유로 완료를 가정하지 않는다.

상태 파일 자체가 없거나 다른 작업의 기록이면 기억을 꾸며내지 않는다. 현재 제공된 사실만으로 새 기록을 만들고, 재개에 필요한 누락을 확인한다. 기존 세션을 다시 열어야만 진행할 수 있는 구조로 만들지 않는다.

## 작업 종료와 검증

단계 완료 시 결과를 의도·제약·설계 기준과 대조하고, 실제 확인한 결과와 미확인 사항을 구분해 기록한다. 전체 완료 시 현재 상태를 완료로 표시하되 기록을 자동 삭제하지 않는다. 재개에 필요한 결정 근거가 최신 작업에 연결되어 있는지 확인하고 불필요한 기록·파일은 정리 후보로만 제시한다.

논문 리서치는 사용자가 명시적으로 요청했을 때만 수행한다. 요청이 없으면 허용된 로컬 자료·공식 문서·실용 구현 자료를 우선한다. 논문을 사용할 때는 출판물과 프리프린트를 구분한다. 한글 PDF를 만드는 작업이면 한글을 지원하는 폰트와 출력 설정으로 렌더링을 검증한다.

## 피해야 할 실수

- 최신 작업만 남기고 그 작업을 선택한 이유를 지우는 것.
- 완료 내역을 지우면서 아직 유효한 제약·실패 원인까지 없애는 것.
- “문서 하나”를 지키면서 별도 로그나 숨겨진 아카이브를 늘리는 것.
- 2,000토큰에 맞추려고 자동 압축하거나 3,000토큰 이후에도 묻지 않고 누적하는 것.
- 기록에 적힌 목표나 계획을 실행·검증이 끝난 사실로 보고하는 것.
